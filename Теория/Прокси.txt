1. Цель занятия
На предыдущей лекции мы разобрали теорию прокси-серверов. Сегодня реализуем простейший HTTP-прокси на Python, используя стандартную библиотеку `socket`.  

Что сможет наш прокси:
✅ Принимать HTTP-запросы от клиента (например, браузера).  
✅ Перенаправлять их на целевой сервер.  
✅ Возвращать ответ клиенту.  

Что НЕ будет (пока!):
❌ Поддержка HTTPS (это сложнее, требует работы с SSL).  
❌ Кэширование и балансировка нагрузки.  

---

2. Архитектура прокси
	1. Клиент (браузер) → подключается к прокси (`localhost:5050`).
	2. Прокси → принимает запрос, извлекает `Host`, отправляет запрос на целевой сервер.  
	3. Целевой сервер → возвращает данные прокси.  
	4. Прокси → передаёт ответ клиенту.

---

3. Код простого HTTP-прокси
```python
import socket
import threading

def handle_client(client_socket):
    # 1. Получаем HTTP-запрос от клиента
    request = client_socket.recv(4096).decode('utf-8')
    print(f"Получен запрос:\n{request}")

    # 2. Извлекаем Host (куда нужно перенаправить запрос)
    host = request.split('Host: ')[1].split('\r\n')[0]
    if ':80' in host:
        host = host.replace(':80', '')

    # 3. Подключаемся к целевому серверу
    try:
        remote_socket = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
        remote_socket.connect((host, 80))
        remote_socket.send(request.encode())

        # 4. Получаем ответ и отправляем клиенту
        response = remote_socket.recv(4096)
        while len(response) > 0:
            client_socket.send(response)
            response = remote_socket.recv(4096)

    except Exception as e:
        print(f"Ошибка: {e}")
    finally:
        client_socket.close()
        remote_socket.close()

def start_proxy_server():
    proxy_socket = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
    proxy_socket.bind(('0.0.0.0', 5050))
    proxy_socket.listen(5)
    print("Прокси запущен на http://localhost:5050")

    while True:
        client_socket, addr = proxy_socket.accept()
        print(f"Подключение от {addr}")
        threading.Thread(target=handle_client, args=(client_socket,)).start()

if __name__ == "__main__":
    start_proxy_server()
```

---

4. Разбор кода 

	4.1. Основные компоненты 
		- `socket.socket()` – создаём TCP-сокет.  
		- `bind(('0.0.0.0', 5050))` – слушаем все интерфейсы на порту 5050.
		- `listen(5)` – очередь из 5 клиентов.  

	4.2. Обработка запроса
		1. Извлечение `Host` 
   			- Запрос клиента выглядит так:  
     			```
     			GET / HTTP/1.1
     			Host: example.com
     			... 
     			```
   			- Мы вырезаем `example.com` из заголовка `Host`.  

		2. Перенаправление запроса
   			- Создаём новое соединение к `example.com:80`.  
   			- Отправляем исходный запрос "как есть".  

		3. Пересылка ответа
   			- Читаем данные от сервера чанками по 4096 байт и отправляем клиенту.  

	4.3. Многопоточность
		- Каждый клиент обрабатывается в отдельном потоке (`threading.Thread`), чтобы прокси мог обслуживать несколько запросов одновременно.

6. Ограничения и улучшения
	6.1. Что не так с этим кодом?
		- Нет поддержки HTTPS – нужно работать с SSL/TLS (можно использовать `http.server` или библиотеку `pyOpenSSL`).  
		- Нет кэширования – можно добавить `dict` для хранения ответов.  
		- Уязвимость к атакам – нет проверки заголовков (`X-Forwarded-For`).  

	6.2. Как можно улучшить?
		1. Добавить HTTPS (через `CONNECT`-метод для туннелирования).  
		2. Реализовать кэширование (сохранять ответы от сервера в памяти).  
		3. Логирование (записывать запросы в файл).

Отличный вопрос! Давайте разберём, зачем в прокси-сервере нужны кэширование и логирование, и как они улучшают его функциональность и безопасность.

---

1. Кэширование в прокси-сервере 
3ачем нужно?
	1. Ускорение работы  
   		- Если несколько пользователей запрашивают один и тот же ресурс (например, главную страницу `google.com`), прокси может не загружать его 		повторно с сервера, а отдать сохранённую копию.  
   		- Это особенно полезно для статического контента (CSS, JS, изображения).  

	2. Снижение нагрузки на сеть  
   		- Меньше запросов к удалённым серверам → экономия трафика.  
   		- Полезно в корпоративных сетях, где много пользователей обращаются к одним и тем же сайтам.  

	3. Резервирование при недоступности сервера
   		- Если целевой сайт "упал", прокси может отдать закэшированную версию (если она есть).  

Как реализовать?
		- Использовать словарь (`dict`) или Redis для хранения ответов.  
		- Ключом может быть `URL + заголовки`, значением — тело ответа.  
		- Добавить TTL (время жизни кэша), чтобы данные не устаревали.  

Пример простого кэширования
```python
cache = {}

def handle_client(client_socket):
    request = client_socket.recv(4096).decode()
    host = request.split('Host: ')[1].split('\r\n')[0]
    url = host + request.split(' ')[1]  # Пример ключа: "example.com/index.html"

    if url in cache:
        print("Отдаём закэшированный ответ")
        client_socket.send(cache[url])
        client_socket.close()
        return

    # Если нет в кэше — идём в сеть
    remote_socket = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
    remote_socket.connect((host, 80))
    remote_socket.send(request.encode())

    response = b""
    while True:
        data = remote_socket.recv(4096)
        if not data:
            break
        response += data

    cache[url] = response  # Сохраняем в кэш
    client_socket.send(response)
    client_socket.close()
```

2. Логирование в прокси-сервере
	Зачем нужно?
	1. Мониторинг активности
   		- Можно отслеживать, какие сайты посещают пользователи.  
   		- Полезно для корпоративных прокси (например, чтобы запретить соцсети в рабочее время).  

	2. Анализ проблем
   		- Если пользователь жалуется, что "сайт не грузится", логи помогут найти ошибку (например, `502 Bad Gateway`).  

	3. Безопасность 
   		- Логи могут выявить подозрительные запросы (например, сканирование уязвимостей или DDoS-атаки).  
   		- Пример: если один IP делает 1000 запросов в секунду → возможен бот.  

	4. Статистика
   		- Можно строить графики: "Какие ресурсы самые популярные?", "Когда пиковая нагрузка?"  

Как реализовать?
	- Писать логи в файл или базу данных (например, SQLite или Elasticsearch).  
	- Формат записи:  
  	```plaintext
  	[2023-10-25 14:30:45] 192.168.1.1 GET example.com/index.html 200 OK
  	[2023-10-25 14:31:02] 192.168.1.2 POST api.com/login 403 Forbidden
  	```  

Пример логирования
```python
import datetime

def log_request(client_ip, method, url, status):
    timestamp = datetime.datetime.now().strftime("%Y-%m-%d %H:%M:%S")
    log_entry = f"[{timestamp}] {client_ip} {method} {url} {status}\n"
    
    with open("proxy.log", "a") as f:
        f.write(log_entry)

# В функции handle_client():
log_request(addr[0], request.split(' ')[0], url, "200 OK")
```

3. Когда кэширование и логирование могут быть вредны?
Кэширование: 
	- Устаревшие данные – если сайт обновился, а прокси отдаёт старую версию.  
	- Конфиденциальность – если в кэш попали личные данные (например, почта).  

Решение: 
	- Добавлять `Cache-Control` заголовки.  
	- Не кэшировать敏感-запросы (например, с `Cookie`).  

Логирование: 
	- GDPR и приватность – в некоторых странах нельзя логировать персональные данные без согласия.  
	- Дисковое пространство – логи могут быстро заполнить сервер.  

Решение:
	- Очищать логи через `logrotate`.  
	- Не сохранять тело запросов (только метаданные).

|-------------|-------------------------------------------------|-------------------------------------|
| Кэширование | Ускорение, экономия трафика, отказоустойчивость | Устаревшие данные, утечки           |
| Логирование | Безопасность, мониторинг, дебаг                 | Нарушение приватности, объём данных |

Оптимальный подход:  
	- Кэшируйте только статику (CSS, JS, картинки).  
	- Логируйте только метаданные (URL, статус, IP, но не пароли).
